# 계층 인터페이스 (Layer Interfaces)

Black-Shell 워킹 스켈레톤의 **계층별 계약**을 못 박는 문서 모음이다. 코드보다 먼저 이 계약을 고정하는 이유는 [`BlackShell_Plan.md`](../BlackShell_Plan.md) §9의 관리 전략 때문이다 — 끝-끝 파이프라인을 더미(항등) 패스로 먼저 뚫고, 더미를 실제 패스로 **무중단 교체**하려면 더미와 실제가 **같은 계약**을 지켜야 한다.

## 레이어 지도

```
[외부]  JS 껍데기 (bin/blackshell.js)
          │  argv를 최초 수신 → 메타질의(version)만 즉답, 나머지는 그대로 forward
          ▼  ── 01. CLI 이음매 (argv in / stdout·exit out) ──
[내부]  엔진 드라이버           ── 02. 드라이버 (명령 문법·토글·파이프라인 순서) ──
          │  파싱·디스패치·레벨 토글
          ▼
        게이트 (IR → 통과|거부)   ┐
        노이징 (IR → IR, L1~L3)   ┘ ── 04. 패스 계약 ──
          │
          ▼
        토이 IR 모델             ── 03. IR 모델 (자료구조·격리 메모리) ──
          ▲
        인터프리터/러너
          ▲
        등가검증 하네스 (L0 vs 변환, 매 패스) ── 05. 하네스 ── (전체를 가로지름)
```

## 언어 배치 (확정)

"**외부는 JS, 실행은 내부.**" 자세한 근거는 메모리 `language-layering` / [`BlackShell_Plan.md`](../BlackShell_Plan.md) §6 '언어 슬롯 셋'.

| 계층 | PoC (지금) | 프로덕션 | 비고 |
| --- | --- | --- | --- |
| 외부/패키징 | **JS** | JS | npm·릴리스·version·론처 |
| 내부 실행(드라이버~파이프라인) | **Python** | **C++** (단일 네이티브 바이너리) | 경계 = 서브프로세스(PoC) → C-ABI(프로덕션) |
| 등가검증 하네스 (§6 정확성) | **Python** | **C++** | 엔진의 일부, 배포됨 (`enshell --verify`) |
| 재사용성·AI저항 벤치마크 (§9 페3) | **Python** | Python | 별도 dev/CI 도구, 배포 경로 밖 |

## 공통 규약

- **의미 보존이 최상위 불변식.** 노이징·드라이버·IR 어떤 변경도 등가 하네스(05)를 깨면 안 된다.
- **PoC→프로덕션에서 바뀌는 건 "패스 몸통"뿐.** 이 문서들이 정의하는 *계약*(경계·문법·IR 모양·패스 시그니처·검증)은 그대로 넘어간다. §9 "다시 쓰는 건 IR을 실제로 만지는 패스 몸통뿐"의 집행 장치가 이 폴더다.
- **더미 게이트 주의.** accept-all 게이트는 "봉인됨"이라는 거짓 확신을 준다. 출하 전 반드시 실제 게이트로 교체(각 문서의 "출하 전 체크" 참고).
