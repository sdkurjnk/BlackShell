# 03. 토이 IR 모델

> 고정하는 계약: PoC 파이프라인이 주무르는 중간 표현의 자료구조와 격리 메모리 모델. 인터프리터 입력이자 패스 입출력.

§9 페이즈1의 "작은 명령어 서브셋(산술, 로드/스토어, 분기 몇 개)"을 구체화한다. **토이**인 이유: PoC는 네이티브·멀티ISA가 목표가 아니라 개념 증명이라 인터프리트가 허용됨. 프로덕션에선 이 토이 IR이 **LLVM IR로 대체**되지만, 아래 *모양*(함수=입력→출력, 격리 메모리, 3-주소 명령)은 LLVM IR에도 그대로 성립해 패스 사고방식이 이어진다.

## 직렬화

**JSON**으로 표현한다 (PoC 언어가 JS/Python이라 자연스럽고, 덤프·검사·하네스 전달이 쉬움).

```json
{
  "name": "seal_unit",
  "params":  ["a", "b"],
  "returns": ["r"],
  "locals":  ["t0", "t1"],
  "blocks": [
    { "label": "entry", "insts": [
        { "op": "const", "dst": "t0", "imm": 2 },
        { "op": "add",   "dst": "t1", "lhs": "a", "rhs": "t0" },
        { "op": "br",    "cond": "t1", "then": "L1", "else": "L2" }
    ]},
    { "label": "L1", "insts": [ { "op": "mov", "dst": "r", "src": "t1" }, { "op": "ret" } ]},
    { "label": "L2", "insts": [ { "op": "mov", "dst": "r", "src": "b"  }, { "op": "ret" } ]}
  ]
}
```

## 구조

| 요소 | 설명 |
| --- | --- |
| **모듈/함수** | 봉인 유닛 하나 = 함수 하나. `params`(입력 값), `returns`(출력 값), `locals`(가상 레지스터). |
| **블록** | `label` + 순차 명령 리스트. 제어흐름은 블록 간 분기로만. |
| **값** | 이름 붙은 가상 레지스터(파라미터·로컬). PoC는 정수 스칼라만(타입 단순). |

## 명령어 집합 (최소)

| 분류 | op | 형태 |
| --- | --- | --- |
| 상수 | `const` | `dst = imm` |
| 이동 | `mov` | `dst = src` |
| 산술 | `add` `sub` `mul` | `dst = lhs ∘ rhs` |
| 비트 | `and` `or` `xor` `shl` `shr` | `dst = lhs ∘ rhs` |
| 메모리 | `load` `store` | 로컬 스토어 인덱스 접근 (아래 격리 규칙) |
| 분기 | `br` | `cond` 참이면 `then`, 아니면 `else` 블록 |
| 점프 | `jmp` | `target` 블록 |
| 반환 | `ret` | `returns`의 값들을 출력 |

> 산술+비트를 함께 둔 건 **L3 MBA**(산술·논리 혼합식)를 PoC에서 돌려보기 위한 최소 집합이다. carry-sensitive 혼합을 표현하려면 이 둘이 한 IR에 공존해야 한다.

## 격리 메모리 모델 (§5 조건1의 IR 표현)

이 IR이 **call-by-value·외부 비공유**를 구조적으로 강제한다:

- 모든 상태는 함수 **전용 로컬 스토어**에만 존재. `load`/`store`는 그 전용 스토어 인덱스만 접근.
- **외부 포인터·전역·I/O를 가리키는 명령이 IR에 아예 없다.** → 포인터로 외부를 건드릴 표현 수단 자체가 없음.
- 입출력은 `params`/`returns`의 **값 복사**로만.

게이트(문서 04)는 이 모델 위에서 "외부 참조가 있는가"를 검사한다. PoC IR에선 외부 참조를 **표현할 수 없게** 설계하는 게 1차 방어이고, 게이트는 (프로덕션 LLVM IR처럼 외부 참조가 표현 *가능한* 경우를 대비한) go/no-go 판정이다.

## 불변식

- IR는 패스 입출력의 **공통 화폐**다. 모든 노이징 패스는 유효한 IR을 받아 유효한 IR을 낸다(문서 04).
- 인터프리터(러너)는 이 IR + 입력 벡터 → 출력 벡터. 등가 하네스(문서 05)가 이 실행 결과를 비교한다.

## PoC → 프로덕션

- **바뀌는 것:** 토이 IR → LLVM IR. 직렬화(JSON) → LLVM 인메모리/비트코드.
- **안 바뀌는 것:** 함수=값입력→값출력, 격리 메모리, 3-주소/블록 구조. 패스가 "무엇을 변형하는지"의 멘탈 모델.
