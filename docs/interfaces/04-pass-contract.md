# 04. 패스 계약

> 고정하는 계약: 파이프라인에 꽂히는 모든 패스가 지켜야 하는 시그니처. — §9 척추 ① '패스 계약'. **워킹 스켈레톤의 핵심** — 더미와 실제가 이 계약만 같으면 무중단 교체된다.

패스는 **두 종류**뿐이다. 종류별로 시그니처가 정해져 있고, 더미든 실제든 반드시 이 모양을 지킨다. 패스는 **출력(print)하지 않는다** — 실패·거부는 `EngineError`/verdict로 드라이버에 올리고, 렌더는 드라이버가 한다(문서 02 에러 처리).

## 종류 1 — 노이징 패스 `IR → IR`

```
transform(module: IR) -> IR      # 의미 보존, 순수 함수
```

- **입력·출력 모두 유효한 IR**(문서 03). 입력을 파괴하지 않음(순수 함수로 취급).
- **의미 보존이 절대 불변식.** 같은 입력에 같은 출력. 등가 하네스(문서 05)가 매 패스 뒤 이를 지킨다 — 깨지면 그 패스가 버그.
- 레벨(L1/L2/L3)과 이름을 메타로 가진다 → 드라이버(문서 02)의 `--level` 토글이 레지스트리에서 선택.

| 레벨 | 실제 패스 (나중에 교체) | 더미 (지금) |
| --- | --- | --- |
| L1 | 명령어 치환·더미 삽입·재배치 | **항등**(그대로 반환) |
| L2 | 간접 분기·불투명 술어·평탄화 | **항등** |
| L3 | carry-sensitive MBA | **항등** |

> 더미 노이징(항등)은 "정확하지만 보호 안 됨"이라 **안전하다.** 끝-끝 초록불을 먼저 만드는 용도. 실제로 교체해도 하네스가 통과하면 OK.

## 종류 2 — 게이트 패스 `IR → {통과 | 거부}`

```
check(module: IR) -> Verdict
# Verdict = { ok: true } | { ok: false, reason: str, violations: [...] }
```

- **IR를 수정하지 않는다**(read-only 판정만).
- §5 **조건1(외부 메모리 비공유)** 위반을 검사. 위반 시 `ok:false` + 위반 지점 목록.
- 드라이버는 `ok:false`면 **파이프라인 중단 + exit 2**(문서 01·02). 노이징 진입 금지.

| | 실제 게이트 (나중에 교체) | 더미 (지금) |
| --- | --- | --- |
| 동작 | 외부 참조·전역·I/O·포인터 유입 검사 후 판정 | ⚠️ **accept-all**(`ok:true`) |

> ⚠️ **더미 게이트는 위험하다.** accept-all은 "봉인됨"이라는 **거짓 확신**을 준다(더미 노이징과 달리 안전하지 않음). 끝-끝 배선용으로만 쓰고, **출하 전 반드시 실제 게이트로 교체.** README·문서 02의 경고와 동일.

## 레지스트리 + 토글

- 모든 패스는 `(이름, 종류, 레벨)`로 **레지스트리에 등록**된다.
- 드라이버가 `--level`로 노이징 패스를 뽑고, 게이트는 항상 노이징 앞에 선다.
- 더미→실제 교체 = **레지스트리에서 같은 이름/레벨의 구현을 바꿔 끼우는 것.** 호출부(드라이버)·계약은 안 바뀐다.

## PoC → 프로덕션

- **바뀌는 것:** `IR` 타입(토이 JSON → LLVM IR), 패스 몸통(Python 항등/간단 변환 → C++ LLVM 패스).
- **안 바뀌는 것:** **두 시그니처**(`IR→IR`, `IR→Verdict`), 의미 보존 불변식, 게이트-앞/노이징-뒤 순서, 레지스트리+토글 방식. → OLLVM 포크 통합(L1/L2)과 자체 L3 MBA 모두 이 계약에 맞춰 들어온다.
